## 目的

Cornix LP の利用者が、Vial の機能名を知らなくてもキーごとの動作を直感的に設定し、キーマップをキーボードへ書き込めるサイトを提供する。
当面は投稿者本人が利用し、URL は誰でもアクセスできるが、一般への告知は行わない。

## 完了条件

- [ ] デスクトップ版 Chrome または Edge から Cornix に Bluetooth 接続し、レイアウト・対応機能・各機能の枠数を本体から読み取って表示できる。USB 接続にも対応し、非対応ブラウザーでは常時警告を表示する
- [ ] レイヤーごとにキーのタップ・長押し・2回タップ・タップ後長押しを設定でき、対応するレイヤー切替、Tap Dance、Combo、ロータリーエンコーダーも編集できる
- [ ] 入力内容から機能を自動判定して枠を管理し、枠不足時は対象キーを示す。未対応機能が設定済みのキーは内容を保持して編集不可と表示し、透過キーには実際に有効な下位レイヤーの動作を表示できる
- [ ] `.vil` ファイルを保存・読み込みできる。書き込み前に変更一覧の確認・取り消しと設定の自動バックアップからの復元ができ、書き込み後の再読み込みで設定を照合できる
- [ ] 編集・書き込みの失敗時に原因と対象、再試行または復元など次の操作を表示できる

## やらないこと

- Cornix 以外の機種、Vial 非対応の Orca echo への対応、および Cornix の ZMK 化
- マクロ、Key Override、QMK Settings・タイミング設定、ライティング、マトリクステスター、動作シミュレーション
- 基本レイヤー変更（DF）、タップ回数によるレイヤー切替（TT）
- Mac/Windows 用キーマップ切替、接続先 OS の US/JIS 配列に応じた記号変換
- アカウントやサーバーへの設定保存

## 制約

- 対象は標準ファームウェアが RMK で Vial 対応の Cornix LP のみ。レイアウト・対応機能・枠数は接続時に本体から取得する
- デスクトップ版 Chrome/Edge の WebHID を利用する。Bluetooth 接続を必須とし、USB 接続にも対応する
- TypeScript、React、Vite を使ったサーバーなしの静的サイトとし、GitHub Pages で公開、GitHub Actions で自動デプロイする。public リポジトリを使い、費用は無料枠内に限定する
- URL は誰でもアクセス可能とするが、当面は投稿者本人が利用し、一般への告知は行わない
- Vial プロトコルは UI から分離して TypeScript で実装する。設定データの保存先はキーボード本体、`.vil` ファイル、ブラウザー内の自動バックアップに限る
- 初期作業では対応機能・枠数・レイアウトの読み出しと Bluetooth 通信を確認し、その結果を踏まえて自動判定ルールの細部を確定する。タイミング設定は編集せず、本体の既存値を使う

## 詳細要件

元の要件定義「Cornix キーマッピングサイト 要件定義」（2026-10-04 作成）の要約。

### 背景

既存の web 版 Vial の不満点:

- Tap Dance が番号管理で、キーに何が割り当たっているか分かりにくい
- 長押しの動作を変えるには、先に Tap Dance 画面で内容を作ってからキーに割り当てる遠回りが要る
- MO / LT / MT / Tap Dance の違いが初心者に分かりにくい

### 対象

- 利用者は当面本人のみ。公開できる品質になったら、他の Cornix ユーザー向けの公開を検討する
- 対象機器は Cornix（標準ファームウェア RMK、Vial 対応）のみ
- キー配列はハードコードせず、接続時に本体からレイアウト定義を取得して描画する
- 使える機能と枠数も、接続時に本体から取得して判定する（RMK の Vial 実装は QMK 版と差がありうる）

### 初版に含める機能

- キーマップ編集（レイヤー含む）
- レイヤー切り替え
- Tap Dance
- Combo
- ロータリーエンコーダーの設定
- 設定ファイル（`.vil`）の保存・読込

### UI

- キーを選ぶと、その場で「タップ」「長押し」「2回タップ」「タップ後長押し」の各欄を編集できる
- Tap Dance の番号はサイトが自動で採番・解放し、利用者に見せない
- キーの上には、番号ではなく割り当てた動作を表示する（例: タップ=A、長押し=Ctrl）
- 機能名は平易な日本語で表示する（例: MO(1) は「押している間だけレイヤー1」）
- Vial で設定済みの Tap Dance やレイヤー切替キーも、同じ形式に変換して表示する
- 動作は「文字・数字」「修飾キー」「ショートカット」「レイヤー切り替え」「メディア・その他」などの分類から選ぶ。名前で検索もできる。実際にキーを押して取り込む方式は採用しない
- 刻印は US 配列で固定
- 透過キーは、実際に効く下のレイヤーの動作を薄く表示する。空のキーには「透過」と「何もしない」を選べる
- 後回しにした機能（マクロなど）が割り当て済みのキーは「このサイトでは編集不可」と表示して内容を保持する。別の動作での上書きはできる
- ロータリーエンコーダーはキーボード図に表示し、「右回し」「左回し」それぞれに動作を割り当てる
- 「キーマップ」と「コンボ」はタブで切り替える。コンボは「コンボを追加」から複数キーをクリックして動作を入力する。キーマップタブにはコンボの線や色を出さない

### レイヤー切り替え

- 機能名ではなく「レイヤー切り替え」という動作として各欄に割り当て、切り替え方式と切り替え先レイヤー番号を入力する
- 初版に含める方式: 押している間だけ（MO）、押すたびにオン・オフ（TG）、そのレイヤーに移動（TO）、次の1キーだけ（OSL）
- RMK が対応していない方式は選択肢に出さない

### 機能の自動判定

利用者は機能名を選ばない。入力内容から、枠を消費しない軽い機能を優先してサイトが選ぶ。

| 入力内容 | 選ぶ機能 |
| --- | --- |
| タップのみ | 通常のキー |
| 長押しのみでレイヤー切替 | MO |
| タップ＋長押し（長押しが修飾キー） | MT |
| タップ＋長押し（長押しがレイヤー切替） | LT |
| 上記以外（2回タップを使う、など） | Tap Dance |

- 欄の増減で該当行が変わったら機能も自動で切り替え、不要になった Tap Dance の枠は解放する
- 同じ内容のキーは1つの枠を自動で共有する。共有中のキーを変更する時は「連動して変更」か「このキーだけ変更」かを確認し、連動対象のキー位置も示す
- 枠が足りない編集はその場で止め、枠を使っているキーの一覧を示す。残り枠数は常時表示する

### 書き込み

- 編集内容は画面上に溜め、「書き込み」ボタンで一括して反映する。書き込み前に変更点の一覧を確認でき、取り消せる
- 書き込み直前に、現在の設定をブラウザ内へ自動バックアップする。直近の数回分を保持し、書き込み前の状態に戻せる
- 書き込み後に設定を読み直し、意図した内容と一致するか照合する
- 途中で失敗した場合はその旨を表示し、「再試行」と「書き込み前の状態に戻す」を選べる
- Bluetooth 接続での書き込みを必須とする（主な利用形態）。USB 接続にも対応する
- タイミング設定は初版では編集せず、キーボードの既存値を使う

### 対応環境

- デスクトップ版の Chrome と Edge のみ（通信に WebHID が必要なため）
- Safari、Firefox、iPhone、iPad は書き込み不可。非対応ブラウザで開いた時は、画面上部に警告を常時表示する（必須要件）

### 技術構成

- サーバーを持たない静的サイト。GitHub Pages で公開し、GitHub Actions で自動デプロイする
- TypeScript、React、Vite
- Vial プロトコルを TypeScript で自前実装し、UI から分離する（別プロトコルの機器を後から追加できるようにするため）
- データの保存先は、キーボード本体、`.vil` ファイル、ブラウザ内の自動バックアップのみ
- いずれの技術も本人は未経験のため、小さな単位で動作確認しながら進める

### 最初の作業

Cornix から対応機能・枠数・レイアウト定義を読み出すだけの最小版を作り、Bluetooth 接続での通信を確認する。自動判定ルールの細部はその結果で確定する。
